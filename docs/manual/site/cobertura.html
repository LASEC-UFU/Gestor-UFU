Menus, diálogos e interações específicas

  • Menus de contexto: menu de três pontos em cartão Config Moodle; menu de seção/atividade no editor; ações de edição/remoção condicionadas ao registro.
  • Duplo clique: no editor de grade semanal, abre seleção de uma ou mais disciplinas/turmas para o horário.
  • Confirmações: exclusão/substituição, importação completa, preenchimento de diário, alteração de turma e envio ao SEI pedem confirmação antes de concluir em diversos fluxos.
  • Busca e filtros: selecionar docente/disciplina por digitação; filtro de docentes visíveis na distribuição; busca para vincular curso/atividade no Moodle.
  • Calendários: Config Moodle, diário e ajustes de datas usam seletor de data do sistema.
  • Estados condicionais: botões de sincronização/preenchimento ficam desabilitados até haver configuração, vínculo, sessão ou dados necessários.

Atalhos e acessibilidade

Na árvore de rotas e páginas examinadas não foi encontrado um catálogo próprio de teclas de atalho do aplicativo. O uso de TAB/Enter/Espaço segue os controles Flutter padrão. Duplo clique em células da grade e ações por menu de contexto são as interações não óbvias identificadas. Não foi possível conferir atalhos específicos de bibliotecas/diálogos do sistema em todas as janelas.

Perfis e acesso

Não existe cadastro de perfil ou papel dentro do Gestor UFU. As telas e ferramentas ficam no computador do usuário, com visibilidade dos cartões ajustável no painel; ocultar um cartão não configura autorização. A autorização de leitura/escrita remota depende da conta usada no Moodle, Portal do Docente ou SEI.

Cuidados com dados e automação

Antes de sincronizar, inserir documento ou preencher diário, confira curso, turma, processo, datas e usuário. Faça backup de cadastros antes de importações. O Edge autenticado pode conter dados pessoais; não publique capturas nem arquivos de backup sem revisar metadados. Não coloque senhas em exemplos ou repositórios.

Publicação e manutenção

O workflow .github/workflows/pages.yml publica este site estático quando arquivos do manual mudam em main. Para primeira ativação, em Settings → Pages escolha a origem GitHub Actions. Depois, acompanhe Actions → Publicar manual Gestor UFU no GitHub Pages. O site publicado fica no endereço Pages indicado pelo repositório; no projeto, o provável endereço é https://lasec-ufu.github.io/Gestor-UFU/, mas ele só será confirmável após deploy bem-sucedido e configuração da conta Pages.

Estado da publicação nesta execução: a sessão local de GitHub CLI reportou token inválido/HTTP 401. O workflow foi preparado, mas a publicação externa só pode ser confirmada depois de restaurar a autenticação e executar o deploy. Não trate o endereço provável como site publicado até verificar a página ao vivo.

Como atualizar este manual

  1. Quando mudar a versão do Gestor, confira rotas e telas no código e execute a versão correspondente.
  2. Atualize o checklist docs/manual/INVENTARIO.md e as páginas afetadas.
  3. Capture telas em ambiente de demonstração, sem informações pessoais.
  4. Valide links locais, JSON de busca, telas em tamanho de desktop e celular.
  5. Envie as alterações para main e acompanhe a implantação do Pages.
